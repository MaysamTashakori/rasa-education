# استقرار (Deployment)
> وضعیت: فعال · آخرین بازبینی: ۱۲ آبان ۱۴۰۵

وب‌اپ کاملاً ایستا است (پوشهٔ `dist/`)؛ هر سروری با Docker کافی است.

## نشانی‌های فعلی (موقت، تا تحویل سرور اختصاصی)
| نقش | نشانی | توضیح |
|---|---|---|
| اصلی (HTTPS) | https://edu.5-9-89-137.sslip.io/ | nginx میزبان + گواهی Let's Encrypt (`certbot`، نام گواهی `rasa-education`) → کانتینر روی `127.0.0.1:8740` |
| میرور | http://168.119.94.214:8740/ | فقط دانلود فایل تکی و برندبوک |
| میرور | http://157.90.105.119:8740/ | فقط دانلود فایل تکی و برندبوک |

روی نشانی‌های `http://IP:PORT` مرورگر WebCrypto را غیرفعال می‌کند (Secure Context نیست)، پس ثبت‌نام و رمزگذاری فقط روی HTTPS یا فایل تکی دانلودشده کار می‌کند.

## نصب یا به‌روزرسانی روی یک سرور
```bash
git clone https://github.com/MaysamTashakori/rasa-education /opt/rasa-education
RASA_PORT=8740 /opt/rasa-education/deploy/deploy.sh   # همان دستور برای به‌روزرسانی
```
- کانتینر `rasa-education` (nginx:alpine، حافظهٔ حداکثر ۹۶ مگابایت) پوشهٔ `dist` را فقط‌خواندنی سرو می‌کند و به سرویس‌های دیگر سرور دست نمی‌زند.
- مسیرها: `/` وب‌اپ · `/rasa-planner.html` دانلود فایل تکی · `/brand.html` برندبوک · `/healthz` سلامت.

## نکته‌ها
- WebCrypto، نصب PWA و Service Worker فقط روی HTTPS (یا localhost/فایل محلی) فعال می‌شوند؛ برای سرور اختصاصی یک دامنه + گواهی TLS (مثلاً Caddy یا nginx + certbot) جلوی همین کانتینر بگذارید.
- انتقال به سرور اختصاصی: همان دو دستور بالا با پورت دلخواه؛ داده‌های کاربران روی دستگاه خودشان است، پس انتقال سرور هیچ داده‌ای جابه‌جا نمی‌کند.
- میرورها: هر سرور یک کلون مستقل از مخزن است؛ با اجرای دوبارهٔ `deploy.sh` هم‌گام می‌شود.
